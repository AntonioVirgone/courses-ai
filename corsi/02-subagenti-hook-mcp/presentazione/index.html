01 Oltre le skill

Una skill non basta per tutto

Il contesto si riempie

Una review legge decine di file. Se lo fa l'agente principale, tutto quel testo resta nella conversazione. Serve qualcuno che lavori a parte e riporti solo le conclusioni.

Le istruzioni si possono ignorare

«Non riscrivere un ADR» in una skill è un consiglio: il modello di solito lo segue, ma non sempre. Una regola che deve valere sempre va fatta rispettare da un programma.

I dati sono altrove

Il glossario, l'issue tracker, il database: l'agente non li conosce. Serve un modo standard per dargli strumenti che li leggano.

02 Subagenti

Un collega con la sua scrivania

Contesto separato

Ogni subagente lavora nella sua finestra di contesto, con un prompt di sistema e strumenti propri. All'agente principale torna solo il risultato.

Delegato in base alla description

Claude delega da solo quando la richiesta corrisponde alla description. Frasi come «use proactively» lo incoraggiano.

In Claude Code un subagente può a sua volta delegare, fino a tre livelli sotto la conversazione principale. Per impedirlo si toglie Agent dai suoi tools.

In Claude Code, /agents oggi ricorda solo dove stanno i file e come chiedere a Claude di crearli: non è più l'interfaccia guidata delle versioni vecchie.

02 Subagenti

Nel plugin: cartella agents/ e qualche limite

Claude Code

  • I file stanno in agents/ alla radice del plugin.
  • Il nome è plugin:file: team-guardrails:reviewer. Le sottocartelle entrano nel nome.
  • Per sicurezza i subagenti dei plugin ignorano hooks, mcpServers e permissionMode. Hook e server vanno in hooks/hooks.json e .mcp.json del plugin.

Copilot CLI e VS Code

  • Nei plugin la cartella è sempre agents/; la doc consiglia file .agent.md.
  • L'id viene dal nome del file senza .md o .agent.md: reviewer.
  • tools accetta i nomi di Claude come alias: Read, Grep, Glob, Bash. I nomi che non riconosce li ignora.
Non rinominare il file in reviewer.agent.md per far contento Copilot: in un plugin Claude Code prende il nome dal file e il subagente diventerebbe team-guardrails:reviewer.agent.
Questo l'abbiamo verificato con claude plugin details. Per Copilot la doc cita sia agents/nome.md sia agents/nome.agent.md: provatelo con /agent sulla vostra versione.
03 Hook

Un programma che l'agente non può saltare

Un hook è un comando che lo strumento esegue quando succede qualcosa: prima di usare un tool, dopo, all'inizio della sessione. Non lo decide il modello: lo esegue l'harness, ogni volta.

  • Skill: «per favore fai così». Il modello può dimenticarsene.
  • Hook: «non puoi fare altrimenti». Un deny vale in ogni modalità di permesso.
Evento (Claude Code)QuandoMatcher
PreToolUsePrima di un tool; può bloccarlonome del tool
PostToolUseDopo un tool riuscitonome del tool
UserPromptSubmitQuando invii un messaggiono
SessionStartAll'avvio della sessionesì
StopQuando l'agente ha finitono

Sono una selezione: Claude Code documenta una trentina di eventi. /hooks mostra in sola lettura gli hook attivi e da dove arrivano, plugin compresi.

Gli hook di un plugin si attivano quando il plugin è abilitato, non quando si usa una sua skill. Si sommano a quelli di utente e progetto, non li sostituiscono.
03 Hook

Il contratto: JSON in ingresso, codice d'uscita in risposta

hooks/hooks.json
{
  "description": "Un ADR esistente non si riscrive…",
  "hooks": {
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "node \"${CLAUDE_PLUGIN_ROOT}/hooks/protect-adr.js\"",
        "timeout": 10
      }]
    }]
  }
}
stdin dell'hook (estratto)
{
  "hook_event_name": "PreToolUse",
  "tool_name": "Write",
  "tool_input": {
    "file_path": "/…/docs/adr/0001-….md",
    "content": "…"
  }
}
UscitaEffetto su PreToolUse
0Prosegue. Lo stdout può contenere una decisione in JSON.
2Blocca il tool. Lo stderr arriva all'agente come motivo.
altroErrore non bloccante: l'azione prosegue.
Correzione al corso 01: $FILE non è una variabile di Claude Code. Il percorso si legge da stdin, per esempio jq -r '.tool_input.file_path' | xargs npx prettier --write, come nella guida ufficiale agli hook.
Il codice 1 non blocca: è l'errore più comune negli hook di sicurezza. Se un hook deve far rispettare una regola, esce con 2. In alternativa esce con 0 e stampa un JSON con hookSpecificOutput.permissionDecision uguale a deny.

04 Server MCP

  
Strumenti nuovi, con un protocollo standard

  

    

      
Il Model Context Protocol è il modo standard per dare all'agente strumenti esterni. Un server MCP dichiara i suoi strumenti, con nome, descrizione e schema degli argomenti. L'agente decide quando chiamarli.

      
    
        
  • stdio: lo strumento avvia il server come processo locale e parla con lui su stdin e stdout. È il caso del laboratorio.
    • 
        
  • http: il server è un servizio remoto con un URL.
    • 
        
  • Lo stesso server funziona in Claude Code, Copilot, VS Code e negli altri client MCP.
    • 
      

    

    

      
acme-glossary

      
Legge il CONTEXT.md del progetto e offre due strumenti:

      
    
        
  • list_terms: elenca i termini del glossario.
    • 
        
  • lookup_term: restituisce il significato di un termine, in italiano o col nome usato nel codice.
    • 
      

      
Circa 120 righe di Node.js, senza librerie: si legge in cinque minuti.

    

  

  
Nella realtà si usa l'SDK ufficiale di MCP. Qui scriviamo il protocollo a mano per vedere che non c'è magia: sono messaggi JSON-RPC, uno per riga.

06 Misurare con le eval

  
Il plugin migliora davvero le risposte?

  

    
Due bracci
Ogni caso gira più volte con il plugin e più volte senza. La differenza di punteggio, Δ, dice quanto il plugin aiuta.

    
Grader
regex, tool_used, tool_order e file_exists sono calcolati e gratuiti; llm e baseline chiedono a un modello giudice.

    
Isolamento
Ogni run parte da una cartella vuota, senza le vostre impostazioni, CLAUDE.md o server MCP. Conta solo il plugin.

  

  
Ogni run e ogni giudice è una vera chiamata al modello sul vostro account: le eval costano token. --max-cost-usd mette un tetto. Copilot non ha un equivalente documentato.

  
Serve Claude Code 2.1.269 o successivo e git 2.31 o successivo. I server MCP veri non partono: si usano i mock, file Markdown con la risposta dello strumento.

Il percorso porta a Heimdall

  

    

      
Un plugin per Claude Code e Copilot CLI: parte da un alert di sicurezza di AppScan o SonarQube e arriva a una pull request su Azure DevOps, pronta per la review.

      
Data Retriever → Security Analyst → Supervisor → Resolver → CI → Review umana

      
    
        
  • Non modifica i test.
    • 
        
  • Non fa merge: l'esito è sempre una pull request da rivedere.
    • 
        
  • Ogni passo lascia una traccia leggibile.
    • 
      

      
Da oggi: i quattro agenti di Heimdall sono subagenti. «Test non modificati» e «niente merge» sono hook. Scanner e Azure DevOps arrivano da un server MCP.
